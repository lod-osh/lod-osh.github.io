Writing Samples
Single-Source Authoring with Flare

MadCap Flare is only one of several single-source help authoring tools, but it’s the one I’m most experienced with, and its robust features make it a popular option.

Conditional Text

MadCap Flare provides ways to manage large amounts of content for multiple audiences. The conditional text function lets you mark any content (text, tables, images, or anything else that’s visible on the page) with the conditions under which it will be included or excluded from the content.

For example, suppose you have a troubleshooting guide that you want to make available to anyone, but some of the steps are highly technical and come with some degree of risk, so those steps should only be attempted by a professional. You could offer the document in full, of course, with a callout like “Caution! Only tech support should attempt this step!”

Instead of hoping that non-professionals will follow that warning, you could remove it entirely from the external site accessible to the public by marking the sensitive information with an “INTERNAL” condition in Flare.

The deployment of the conditionals occurs when you configure your publishing targets. You will need at least two targets – one that publishes to your internal site, and one that is public-facing. On the conditional text include/exclude matrix, set the target that publishes to your internal site to INCLUDE the Internal conditional content, and set the target that publishes to the public-facing site to EXCLUDE it.

NOTE: The newer versions of Flare will include non-excluded content by default. That means that if you do not specifically set that condition to be EXCLUDED by that target, it will be included. The best practice is to set each conditional to be explicitly either INCLUDED or EXCLUDED. This will prevent you from accidentally pushing sensitive content to the public, or from excluding it from the audience that should be able to access it.

In addition to using conditional text to internalize sensitive content, here are a few more examples:

  • Exclude images from a text-only version
  • Display larger, easier-to-tap links on the mobile version of your content
  • Create a PDF that uses absolute links while the web version uses relative links. This allows the PDF to open the site directly to the linked information, while preserving the normal behavior of clicking a link on the web version.
Using Flare with Other Users

If multiple technical writers are working in Flare on content that overlaps or even connects in any way, it’s important to communicate your intended publish schedule with the team to prevent overwriting, deleting, or modifying another writer’s work unintentionally.

There are a variety of ways to manage version control, including MadCap Central and Git. In short, version control is the practice of managing multiple versions of the same content, which involves comparing conflicting content, merging multiple sets of changes, and creating branches. Version control is a safety measure with which developers are already familiar, since they also need to be mindful when pushing their changes.

Master Projects

If you have multiple writers whose work does not usually overlap but needs to connect, you may find that a master project makes the process easier.

In this case, I recommend having one writer serve as “admin” by managing the master project. This is especially useful if you have multiple or unpredictable change or release schedules. Multiple projects can be imported into the master project, which can integrate and publish them all at once. Importing a “sub” project into a master project when a writer has changes to push is also a good way to make sure that stale or unused content is removed regularly.

Example Workflow with a Master Project

Bill, Ted, and Jill manage the company’s product help site. They have divided their work – Bill writes hardware information, Ted writes about the software, and Jill manages the customer message board. Jill works directly in the master project, while Bill works in a Flare project specifically for hardware, and Ted has the project for software.

When Bill has a new hardware document to publish, he lets Ted and Jill know. Meanwhile, Ted is overhauling dozens of topics in his project to make it more user-friendly. When Bill finishes the document, he commits and pushes the changes to his project in the repository. Since the help site is published from the master project, Bill doesn’t need to publish, he just needs to let Jill know about the change.

Jill opens the Import Project dialog in the master project. She has imported the project previously, so the only changed file she sees is Bill’s new document. The Import Project function allows Jill to select any and all files individually. She selects only the new file and imports it to the folder for Bill’s hardware documentation.

At this point, Ted tells Jill that he has committed and pushed his changes in the software project. Jill locates the software project in the repository. Dozens of files have been deleted, added, and edited. In this case, she decides a clean import is called for. She deletes the previously imported version of Ted’s project, then completes a fresh import, marking the Delete Stale Files checkbox to ensure that any files that she previously imported from Ted into the master project will be removed, and that the imported version includes only what Ted intends.

Jill adds some new content of her own in the message board section, then publishes the master project. The changes of all three writers are included.

MadCap Flare cases

I’ve spent many years using Flare, and the following are just a few cases in which I encountered a request or issue, the reason or cause, and my solution.

Interactive Image

ISSUE: The product manager wanted to send clients a link to a webpage that explains the parts of a new user interface to clients.

REASON: The interface is an update of one that clients are familiar with. They know what functions should be there, but they don’t know where to click. There are a lot of buttons, so a simple diagram with callouts could quickly become cluttered and unreadable.

FIX: I created an image map within a Flare topic. Here’s how:

  1. Write a list of every part of the interface that needs detailing.
  2. Create an individual topic for each part of the image (ex. “profile.htm,” “settings.htm,” etc.)
  3. Take a high-resolution screenshot of the interface and insert it in a new Flare help topic.
  4. Right-click the image in the XML editor.
  5. Navigate to Context > Image Map. The Image Map Editor will open.
  6. Select a shape to draw (rectangle, circle, or irregular).
  7. Drag your mouse over the full area of the first part of the interface. The shape will be displayed on the image. The shape will not be visible on the final image, it just separates and defines the boundaries of the areas you want to define.
  8. Select Area Properties.
  9. Set Link to to File in Project. (see note below)
  10. Select the topic that corresponds to the area you defined.
  11. Set the Target Frame to Popup Window if you want the full content of that topic to appear as a popup when the user hovers the mouse over that area. If the topic is more than a sentence or two, you may want to set the Target Frame to New Tab or New Window. You probably want to avoid the Same Window option, since clicking will navigate the user away from the page.
  12. Continue from Step 6 with the next shape until all areas are defined. Avoid overlapping shapes if possible. The overlapping area will usually default to showing the link associated with the top / most recent shape.

NOTE: Alternatively, if you want to keep the content consolidated to one topic, you can add the entire text to the page with the image map. On Step 8, set Set Link to to Place in this Document and select the header or bookmark on that page you want to scroll to when the user clicks there.

PDF Generation

ISSUE: A PDF built in Flare cannot be opened.

Sometimes you can generate a PDF with Flare and see that the build is complete, but clicking it does nothing. It took me some research to discover the cause of this issue, because the error doesn’t occur within Flare itself.

REASON: The culprit is a program called AdobeCollabSync.exe. Adobe says this program assists with shared workflows, but it has only ever caused me problems. This is the program that keeps the PDF from opening.

QUICK FIX:

The following steps will fix the problem in this instance only.

  1. Navigate to Task Manager (CTRL + SHIFT + ESC).
  2. Do only one of the following:
    1. Scroll until you find AdobeCollabSync.exe. Hold CTRL while scrolling to prevent the list from jumping to a different place.
    2. Start typing “adobesync” until AdobeCollabSync.exe is highlighted.
  3. When you find AdobeCollabSync.exe, right-click it and select End Task.
  4. Return to Flare and try to open the PDF again. It should open immediately with no issues.

LONG-TERM FIX:

Assuming you do not want to remove any Adobe applications, this problem will occur again. I find that if it happens once, it will almost certainly happen again until you restart your machine. The following solution will let you avoid having to follow the steps above every time.

  1. Navigate to your desktop by minimizing or closing all open applications or by holding the Windows key and pressing D.
  2. Right-click an empty spot on the desktop and select New > Shortcut.
  3. In the empty location field, enter the following: taskkill /f /im adobecollabsync.exe
  4. Name the shortcut something you will remember, like “Kill AdobeCollabSync.”
  5. Click Finish.

Note: Optionally, you can stop at this point. At any point, you can run the code by navigating to the shortcut and opening it. However, you can follow the next few steps to create a quicker solution.

  1. Right-click your new shortcut, select Properties, click inside the Shortcut key box.
  2. Press the key combination you want to use to run this code, for example CTRL + ALT + K. (Make sure the key combination you select is not already in use.)
  3. Click OK.

Now you can easily open the shortcut and run the code to immediately end the AdobeCollabSync.exe process. If you encounter this issue as often as I have, you should find that this will save you a lot of time in the long-run. When a PDF will not open from the Builds window in Flare, use your keyboard shortcut and try again. The code shouldn’t need more than a second or two to end that process and allow your PDF to open correctly.
